# Slurm Experiment Launch Guide

This guide explains how to easily launch multi-task experiments on slurm and analyze results automatically.

## Quick Start

### 1. Launch an Experiment (One Command!)

```bash
# Launch all algorithms (AR, LT, MDLM) on multiple tasks
./scripts/launch_simple.sh my_experiment bfvp parity arithmetic
```

This submits 9 jobs (3 tasks × 3 algorithms) and creates:
- `experiments/my_experiment/` - All results
- `experiments/my_experiment/analyze.sh` - Run this when jobs finish
- `experiments/my_experiment/status.sh` - Check job status

### 2. Monitor Progress

```bash
# Check status
experiments/my_experiment/status.sh

# Or check queue
squeue -u $USER

# View logs
tail -f watch_folder/my_experiment-*
```

### 3. Analyze Results

```bash
# When jobs complete, run auto-generated analysis
experiments/my_experiment/analyze.sh
```

**That's it!** The analysis script automatically:
- Groups results by language
- Compares algorithms within each task
- Creates cross-language comparisons
- Generates publication-ready plots and tables

## Available Scripts

### `launch_simple.sh` (Recommended)

**Easiest way to run experiments.** Launches AR, LT, and MDLM on specified tasks.

```bash
./scripts/launch_simple.sh EXPERIMENT_NAME TASK1 [TASK2 ...]
```

**Examples:**

```bash
# Single task
./scripts/launch_simple.sh test_bfvp bfvp

# Multiple tasks
./scripts/launch_simple.sh full_study bfvp parity arithmetic

# All FSA tasks
./scripts/launch_simple.sh fsa_study parity contains_a ab_star mod_3
```

**What it does:**
1. Creates `experiments/EXPERIMENT_NAME/` directory
2. Submits 3 jobs per task (AR, LT, MDLM)
3. Stores results in organized structure:
   ```
   experiments/EXPERIMENT_NAME/
   ├── bfvp/
   │   ├── ar/           # AR results for BFVP
   │   ├── lt/           # LT results for BFVP
   │   └── mdlm/         # MDLM results for BFVP
   ├── parity/
   │   ├── ar/
   │   ├── lt/
   │   └── mdlm/
   ├── analyze.sh        # Auto-generated analysis script
   ├── status.sh         # Check job status
   └── config.txt        # Experiment metadata
   ```
4. Creates helper scripts for monitoring and analysis

**After jobs finish:**
```bash
experiments/EXPERIMENT_NAME/analyze.sh
```

Generates:
```
experiments/EXPERIMENT_NAME/analysis/
├── by_language/
│   ├── bfvp/                    # BFVP-specific analysis
│   │   ├── validation_trends_*.png
│   │   ├── test_performance_heatmap.png
│   │   └── test_metrics_comparison.csv
│   └── parity/                  # Parity-specific analysis
│       └── ...
├── combined/                     # All runs together
├── cross_language_acc_exact.png  # Which algo for which task?
├── cross_language_nll.png
└── cross_language_summary.csv    # Full summary table
```

### `launch_experiment.sh` (Advanced)

More control over experiment parameters.

```bash
./scripts/launch_experiment.sh EXPERIMENT_NAME TASK1 [TASK2 ...] [OPTIONS]
```

**Options:**
- `--algos "ALGO1 ALGO2"` - Specify algorithms (default: "ar lt mdlm")
- `--length N` - Model sequence length (default: 128)
- `--steps N` - Training steps (default: 20000)
- `--mem N` - Memory per CPU in MB (default: 32000)
- `--time HH:MM:SS` - Time limit (default: 04:00:00)

**Examples:**

```bash
# Custom algorithms
./scripts/launch_experiment.sh test_ar bfvp --algos "ar"

# Long training
./scripts/launch_experiment.sh long_run bfvp --steps 50000 --time 12:00:00

# Different model sizes
./scripts/launch_experiment.sh size_study bfvp --length 256
```

### `run_single.sh` (Low-level)

Submit a single job manually.

```bash
sbatch \
  --export=ALL,TASK=bfvp,ALGO=ar,MODEL_LENGTH=128,OUTPUT_DIR=path \
  scripts/run_single.sh
```

**Environment variables:**
- `TASK` - Task name (bfvp, parity, etc.)
- `ALGO` - Algorithm (ar, lt, mdlm)
- `MODEL_LENGTH` - Model sequence length
- `OUTPUT_DIR` - Where to save results
- `MAX_STEPS` - Training steps (optional)

## Directory Structure

### Organized Experiments (Recommended)

Using `launch_simple.sh` or `launch_experiment.sh`:

```
experiments/
└── my_experiment/           # One experiment
    ├── bfvp/
    │   ├── ar/
    │   │   ├── validation_metrics.json
    │   │   ├── test_metrics.json
    │   │   └── checkpoints/
    │   ├── lt/
    │   └── mdlm/
    ├── parity/
    │   └── ...
    ├── analysis/            # Generated by analyze.sh
    │   ├── by_language/
    │   ├── combined/
    │   └── cross_language_*.png
    ├── analyze.sh           # Run this when jobs finish
    ├── status.sh            # Check job status
    └── config.txt           # Experiment metadata
```

### Default Hydra Outputs

Using existing scripts (`train_*.sh`):

```
outputs/
└── YYYY-MM-DD/
    └── HH-MM-SS/            # Timestamped run
        ├── validation_metrics.json
        ├── test_metrics.json
        └── checkpoints/
```

You can still analyze these:
```bash
python compare_models.py --run_dirs outputs/2025-*/*/ --output_dir analysis/
```

## Available Tasks

- `bfvp` - Boolean Formula Value Problems
- `arithmetic` - Arithmetic expression evaluation
- `parity` - Parity checking
- `contains_a` - FSA: contains 'a'
- `ab_star` - FSA: (ab)*
- `mod_3` - FSA: modulo 3
- `even_pairs` - FSA: even pairs
- `cycle` - Cycle detection
- `dyck` - Dyck language

## Available Algorithms

- `ar` (or `cot`) - Autoregressive with chain-of-thought
- `lt` (or `looping`) - Looping Transformer with log depth
- `mdlm` (or `mdm`) - Masked Diffusion Language Model

## Complete Workflow Example

### Example 1: Compare Algorithms on BFVP

```bash
# 1. Launch experiment
./scripts/launch_simple.sh bfvp_study bfvp

# 2. Monitor (optional)
experiments/bfvp_study/status.sh

# 3. When jobs finish, analyze
experiments/bfvp_study/analyze.sh

# 4. View results
ls experiments/bfvp_study/analysis/combined/
open experiments/bfvp_study/analysis/combined/test_performance_heatmap.png
```

### Example 2: Compare Across Multiple Tasks

```bash
# 1. Launch full study
./scripts/launch_simple.sh full_study bfvp parity arithmetic

# This submits 9 jobs (3 tasks × 3 algorithms)

# 2. Check status anytime
experiments/full_study/status.sh

# Output shows:
#   ✓ bfvp × ar        (completed)
#   ⏳ bfvp × lt        (running)
#   ⏳ bfvp × mdlm      (pending)
#   ...

# 3. When all complete, analyze
experiments/full_study/analyze.sh

# 4. Key results to check:
open experiments/full_study/analysis/cross_language_acc_exact.png  # Which algo for which task?
open experiments/full_study/analysis/cross_language_summary.csv    # Full summary
```

### Example 3: Custom Configuration

```bash
# Longer training, fewer algorithms
./scripts/launch_experiment.sh long_ar_study bfvp parity \
    --algos "ar" \
    --steps 50000 \
    --time 12:00:00 \
    --mem 64000

# After completion
experiments/long_ar_study/analyze.sh
```

### Example 4: Analyzing Existing Outputs

If you already ran jobs using the old scripts:

```bash
# Find your outputs
ls outputs/2025-01-15/

# Analyze them
python compare_models.py \
    --run_dirs outputs/2025-01-15/*/ \
    --output_dir analysis/jan15/

```

## Monitoring Jobs

### Check Queue

```bash
# All your jobs
squeue -u $USER

# Jobs for specific experiment
squeue -u $USER --name="my_experiment-*"

# Detailed format
squeue -u $USER --format="%.18i %.40j %.8T %.10M %.9l %.6D"
```

### Check Logs

```bash
# Live tail
tail -f watch_folder/my_experiment-bfvp-ar_*.out

# Check all logs for an experiment
ls watch_folder/my_experiment-*
```

### Check Completed Runs

```bash
# Count completed runs
find experiments/my_experiment -name "validation_metrics.json" | wc -l

# Or use the status script
experiments/my_experiment/status.sh
```

## Analysis Output Guide

After running `analyze.sh`, you get:

### Per-Language Analysis (`by_language/{task}/`)

Each task gets its own directory with:

1. **Validation trends** - How each algorithm learns
   - `validation_trends_trainer_nll_global_step.png`
   - `validation_trends_val_acc_exact_global_step.png`

2. **Test comparisons** - Final performance
   - `test_performance_heatmap.png` - Overview of all metrics
   - `test_comparison_acc_exact.png` - Bar chart for accuracy
   - `test_metrics_comparison.csv` - Full table

3. **Decoding strategies** (MDLM only)
   - `decoding_strategies_*_acc_exact.png`
   - Compares: random, top_k, one_level, all_at_once, one_at_a_time

### Cross-Language Summary (root of `analysis/`)

Comparing performance across all tasks:

1. **Heatmaps** - Which algorithm works best where?
   - `cross_language_acc_exact.png` - Accuracy heatmap (Languages × Algorithms)
   - `cross_language_nll.png` - Loss heatmap
   - One heatmap per metric

2. **Summary table**
   - `cross_language_summary.csv` - All metrics for all (task, algorithm) pairs

### Combined Analysis (`combined/`)

All runs analyzed together:
- Useful for seeing overall trends
- Same structure as per-language directories

## Tips and Best Practices

### 1. Naming Experiments

Use descriptive names:
```bash
./scripts/launch_simple.sh baseline_128 bfvp parity      # Good
./scripts/launch_simple.sh test bfvp                     # Less clear
```

### 2. Organizing Experiments

Create separate experiments for different studies:
```bash
./scripts/launch_simple.sh model_size_128 bfvp --length 128
./scripts/launch_simple.sh model_size_256 bfvp --length 256
```

Then compare:
```bash
python compare_models.py \
    --run_dirs experiments/model_size_*/bfvp/ar/ \
    --output_dir analysis/size_comparison/
```

### 3. Incremental Experiments

Add more tasks to existing experiment:
```bash
# Initial run
./scripts/launch_simple.sh study1 bfvp

# Later, add more tasks
./scripts/launch_simple.sh study1_extended bfvp parity arithmetic
```

### 4. Rerunning Analysis

Analysis is non-destructive, rerun anytime:
```bash
# After more jobs complete
experiments/my_experiment/analyze.sh

# Or with custom settings
python compare_models.py \
    --run_dirs experiments/my_experiment/*/* \
    --output_dir experiments/my_experiment/analysis_v2
```

## Troubleshooting

**Q: My jobs are pending forever**

A: Check cluster resources:
```bash
squeue -u $USER
sinfo
```

**Q: Jobs failed, how do I debug?**

A: Check the logs:
```bash
tail -100 watch_folder/my_experiment-bfvp-ar_*.out
```

**Q: Analysis says "No completed runs"**

A: Make sure jobs finished successfully:
```bash
experiments/my_experiment/status.sh
find experiments/my_experiment -name "validation_metrics.json"
```

**Q: How do I cancel jobs?**

A:
```bash
# Cancel all your jobs
scancel -u $USER

# Cancel specific experiment
scancel -u $USER --name="my_experiment-*"

# Cancel specific job
scancel JOBID
```

**Q: How do I rerun a failed job?**

A:
```bash
# Resubmit manually
sbatch \
  --export=ALL,TASK=bfvp,ALGO=ar,MODEL_LENGTH=128,OUTPUT_DIR=experiments/my_experiment/bfvp/ar \
  scripts/run_single.sh
```

**Q: Can I use existing training scripts?**

A: Yes! The existing `train_*.sh` scripts still work:
```bash
sbatch scripts/train_cot.sh bfvp 128
sbatch scripts/train_looping.sh parity 128
sbatch scripts/train_mdm.sh arithmetic 256

# Then analyze
python compare_models.py --run_dirs outputs/2025-*/*/ --output_dir analysis/
```

## Advanced Usage

### Custom Analysis

```bash
# Analyze only specific runs
python compare_models.py \
    --run_dirs experiments/study1/bfvp/* \
    --output_dir custom_analysis/

# Compare specific metrics from different experiments
python compare_models.py \
    --run_dirs experiments/*/bfvp/ar/ \
    --output_dir analysis/ar_across_experiments/
```

### Batch Processing

```bash
# Launch multiple experiments
for task in bfvp parity arithmetic; do
    ./scripts/launch_simple.sh "study_${task}" $task
done

# Analyze each
for exp in experiments/study_*; do
    $exp/analyze.sh
done
```

### Integration with Existing Outputs

```bash
# Copy/link existing runs into experiment structure
mkdir -p experiments/manual/bfvp/ar
ln -s $(pwd)/outputs/2025-01-15/10-00-00/* experiments/manual/bfvp/ar/

# Analyze
python compare_models.py \
    --run_dirs experiments/manual/*/* \
    --output_dir experiments/manual/analysis
```
